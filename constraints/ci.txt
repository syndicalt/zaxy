# Pinned dependency resolution for CI.
#
# Why this exists: CI installed `.[dev]` unpinned, so every run re-resolved the
# whole tree. On 2026-07-21 that silently broke the mypy gate on master with no
# code change -- anyio >= 4.2 retyped `create_memory_object_stream` as a generic
# class and mypy 2.3.0 began reporting it. Master's last green run predated the
# release, so the run list showed nothing wrong.
#
# Constraints only affect how CI and dev environments resolve; they are NOT part
# of the published wheel's metadata, so `zaxy-memory` stays flexible for users.
#
# Resolved against the 3.11 floor and verified to install identically on 3.11,
# 3.12, and 3.13 -- the CI matrix.
#
# To refresh (a deliberate act, in its own PR):
#
#     uv pip compile --extra dev --python-version 3.11 \
#       --output-file constraints/ci.txt pyproject.toml
#
# The scheduled `dependency-drift` workflow resolves unpinned on purpose, so
# upstream breakage surfaces there instead of on someone's unrelated PR.
